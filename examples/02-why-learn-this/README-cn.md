# 为什么先花时间学会用 AI Agent

> 这门课的总纲: 讲清它在整条学习路线里的位置, 以及它的边界在哪.

## 1. 概览

这是整个系列的第一篇正文 (前面那篇是系列索引, 只是一张地图), 你不需要动手做任何事, 只需要花十几分钟, 把一件事想明白: 为什么在学任何别的东西之前, 要先把一款 AI Agent 桌面应用装好, 用起来.

这一篇不教你装, 装是后面的事. 这一篇解决的是 "为什么它排在最前面", 以及 "这门课管什么, 不管什么".

---

## 2. 学习目标

你手上要学, 要做的东西, 大概率比任何时候都多. 但真实情况往往是: 一段话读三遍还是不懂, 一份资料收藏了再也没打开, 一个想做的东西卡在第二步就搁下了. 这不是你不够努力, 是一个人啃硬东西, 效率天然就低.

而有一个 Agent 在旁边陪着你学, 和没有, 差的不是快一点慢一点. 它决定的是你这件事最后学不学得下去. 所以这门课必须排在整条路线的最前面: 它是地基, 不是配件.

学完这个 Task, 你将能够:

1. 说清为什么后面所有的学习与做事, 都建立在会用 AI Agent 之上.
2. 用 mini project 的视角看待你要做的每一件事, 并知道 Agent Skill 在其中的位置.
3. 说清这门课的边界: 教哪三款, 为什么只教 Desktop, 为什么不教 Cursor 那一类.

---

## 3. 前置知识

- 会用电脑, 会上网, 会自己装软件. 不需要任何编程经验, 也不需要任何科技行业背景.
- 会用 GitHub 做最基本的三件事: 创建一个 repo, 把它 clone 到自己电脑上, 改完之后 commit 并 push 回云端. 这门课不负责教这三件事, 具体见第 6 节.

---

## 4. 你将学到什么

一套看待 "怎么做事" 的视角, 加上一张这门课的地图. 读完你会知道自己接下来该读哪几篇, 以及哪几篇跟你无关可以直接跳过.

---

## 5. 有 Agent 和没有 Agent, 是两个物种

先把话说在前面: 这个系列后面所有跟学习有关的内容, 都默认你身边有一个 Agent.

有了它, 你的学习方式会变成这样: 读不懂的段落, 让它换一种说法再讲一遍, 讲到你懂为止; 自以为懂了的地方, 让它出几道题考考你, 看看是真懂还是错觉; 查到一堆零散资料, 让它替你消化成一份你读得下去的笔记; 做出来的东西, 让它帮你挑毛病, 再一起改.

没有它, 你还是老办法: 一个人硬啃, 卡住了就先放着, 放久了就放弃了.

所以这不是 "有个效率工具会更爽" 的问题. 这是能不能坚持学下去的问题. 说得再直接一点: 你要是不会用 Coding Agent, 后面的东西你一件也干不成. 这就是为什么我们要专门花一门课的篇幅, 先把这件事解决掉.

---

## 6. 一个绕不开的前置: 你得有地方存住产出

用 Agent 做事, 会不停地产出东西: 一份文档, 一份研究结论, 一份读书笔记, 一小段代码. 这些东西得有个地方存, 得能改, 还得能回头看清自己改过什么.

这个地方就是 GitHub 上的一个 repo. 你需要习惯这个做法: 一件事就是一个文件夹, 这个文件夹就是一个 repo, 它是你做这件事的容器. 东西都在里面, 改动都有记录, 换台电脑也带得走.

所以这门课对你有一个最低要求, 你至少得会这三件事:

- 在 GitHub 上创建一个 repo.
- 把这个 repo clone 到自己的电脑上.
- 改完东西之后 commit, 再 push 回云端保存.

这三件事这门课不负责教. 如果你还不会, 先去补一下再回来, 网上现成的教程很多, 也就半小时的事. 但请务必先补: 后面每一篇都默认你已经会了.

---

## 7. 把每一件事都当成一个很小的 project

接下来是这门课最重要的一个视角, 值得你慢慢读.

不管是学一个新东西, 读一本书, 写一份报告, 做一个小工具, 还是搞清楚一个你一直没搞懂的概念, 这些事看着五花八门, 其实都可以用同一个姿势对待: 它是一件事, 它有明确的边界, 它有一个产出.

那就把它当成一个 project. 而且是一个非常小的 project, 小到一个文件夹装得下, 小到你能用一句话说清它到底要解决什么.

为什么要这样看? 因为一旦你把一件事框成了一个小 project, 它就从 "一团模糊的焦虑" 变成了 "一个有边界的活儿". 有边界, 才谈得上交给谁去做, 也才谈得上做完没做完.

这个视角是后面所有内容的地基. 你越早习惯它, 后面越顺.

---

## 8. 这个时代最值钱的技能, 是造专家

很多人以为, 用好 AI 的本事是 "知道怎么把问题丢给它". 不是的.

真正拉开差距的是另一件事: 你拿到一个问题, 先不急着问, 而是先给它归类. 这是哪一类问题? 这类问题需要一个什么样的专家来处理? 这个专家该懂什么, 该按什么套路做事, 该输出成什么样? 想清楚之后, 你把这个专家造出来.

造出来的这个东西, 在 Agent 的世界里有个专门的名字, 叫 **Agent Skill**.

Skill 的本质很朴素: 你可以把 Agent 的任何一种能力打包成一个 Skill. 一段脚本可以, 一段提示词可以, 一个人设可以, 一个知识库也可以, 混在一起当然更可以. 打包好之后, 下次再遇到同一类问题, 你不用从头交代一遍来龙去脉, 直接把这个专家叫出来干活.

那一个 Skill 该管多大范围? 答案就是上一节那个 mini project: **一个 Skill 管一类事, 它的边界就是那个小 project 的边界.** 这两个概念是配套的.

Agent Skill 是你后面用得最高频的东西, 没有之一. 但这门课只让你知道有这么个东西, 并且在装完工具之后, 带你亲手做一个极其简单的 summarize skill, 让你真切体验一次它是什么感觉. 仅此而已. 真要展开讲, 那是另外好几门课的量, 不在这里.

---

## 9. 我们只教三家, 只教 Desktop

做基座模型这件事, 全世界能站在第一梯队的就三家, 各有各的地盘:

- **Anthropic**, 模型叫 Claude. 它在美国企业里的口碑和采用规模目前最强, 是企业最认的一家.
- **OpenAI**, 模型叫 GPT, 产品就是大家最熟的 ChatGPT. 它是面向普通民众用得最多的一家.
- **Google**, 模型叫 Gemini. 背靠大厂, 平台底子厚, 属于后发但势头很猛的那一个.

对应到桌面上的 Agent 工具, 就是这门课要教的三款: **Claude Code, Codex, Antigravity**.

两个边界说在前面. 第一, 我们只讲 **Desktop** 版本, 也就是装在你电脑上, 有窗口有按钮, 点点鼠标就能用的那种形态. 这门课面向任何水平的读者, 不要求你有科技行业背景, 也不要求你变成电脑专家. 第二, 这三款你**只需要选一款学**, 不用全学. 怎么按自己的处境选, 是第 04 篇的事.

---

## 10. 为什么不教 Cursor 那一类

你多半听说过 Cursor 这类产品, 它们通常被叫做 Coding IDE. 为什么这门课一句不提?

理由只有一条: **它们不跟着模型走.** 这类产品自己不做模型, 用的是别人家的模型. 它们做的是外面那层壳.

而这个行业里最深的护城河, 恰恰就是模型本身. 下一篇会把这件事讲透, 这里你先记住结论: 模型是大脑, 外面那层软件只是壳; 大脑只有那么几个, 壳可以有很多层, 也随时可以被换掉. 一个只有壳, 没有自己大脑的产品, 护城河是很薄的, 说不定哪天就没了. 到那时候, 你花在它身上的学习时间也跟着一起没了.

这里要拦一个可能的误会: 判断标准不是 "它长得像不像一个 IDE". Antigravity 本身也是 IDE 形态, 我们照样教. 判断标准是**它背后有没有自己的大脑**. Antigravity 背后是 Google 自己的 Gemini, 所以它跟着模型走; Cursor 背后不是自己的模型, 所以它不跟.

我们只学护城河最深的那三家: 自己做模型, 又自己做 Agent 的那三家. 学费 (你的时间) 只投给不容易消失的东西.

## 11. 练习

### 练习: 给自己找三个 mini project

**目标:** 把第 7 节那个视角, 用在你自己真实的事情上.

**怎么做:**

1. 拿一张纸或者开一个空文档, 写下你最近真的想学或者想做的三件事. 越具体越好, 别写 "学英语" 这种.
2. 给每一件事补上一句话: 它要解决什么, 做完之后手上会多出一个什么东西 (一份笔记? 一份报告? 一个能跑的小工具?).
3. 看看这三件事, 是不是每一件都能塞进一个文件夹里.

**你会观察到:**

有些事你一句话就能说清, 有些事你会发现自己根本说不清它要解决什么. 说不清的那些, 通常不是难, 而是太大了, 得先拆.

> **关键洞见:** 一件事能不能被框成一个小 project, 是它能不能被交出去做的前提. 你说不清的东西, 谁也帮不了你, AI 也一样.

---

## 12. 回顾: 我们学到了什么

- 后面所有的学习和做事都默认你身边有一个 Agent. 有和没有, 差的不是效率, 是能不能坚持下去. 所以这门课排在最前面.
- 你需要一个地方存住产出, 这个地方就是 GitHub 上的 repo. 会建 repo, 会 clone, 会 commit push, 是这门课唯一的硬前置, 我们不教.
- 任何一件事都可以当成一个非常小的 project 来对待: 有边界, 有产出, 一个文件夹装得下.
- 最值钱的技能不是会提问, 而是会给问题归类, 然后造一个对应的专家. 这个专家在 Agent 世界里叫 Agent Skill, 它的边界正好就是一个 mini project 的边界.
- 这门课只教 Claude Code, Codex, Antigravity 三款的 Desktop 版本, 三选一即可. 不教 Cursor 那一类, 因为它们背后没有自己的模型.

---

## 13. 导师寄语

**为什么这一篇重要:**

大部分人学 AI 工具, 是从 "教程第一步: 打开官网" 开始的. 装完了, 会点几下了, 然后呢? 然后就没有然后了, 因为他们始终没想明白这东西在自己的生活里到底占什么位置.

这一篇存在的唯一目的, 就是让你在动手之前先把位置想清楚. 你装的不是一个软件, 你是在给自己后面几年的学习方式换一套地基.

**关键洞见:**

- 工具会换, 视角不会. 三款工具里哪一款最强, 一年之后可能就变了; 但 "把一件事框成一个小 project, 然后为这类事造一个专家" 这个视角, 会一直有用.
- 你的时间是最贵的成本. 把它投给护城河深的东西, 别投给随时可能消失的壳.
